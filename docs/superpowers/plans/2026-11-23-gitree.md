# gitree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standalone terminal app, `gitree`, that shows a repo's commit history as a GitKraken-style table (branch labels, column-colored graph, message, author, date, hash) using lazygit's graph renderer, with a file/diff preview, a detail panel, GitHub PR status and a small set of safe git actions.

**Architecture:** Go module with four internal layers: `git` (reads and actions via the `git` CLI), `github` (PRs via `gh`), `graph` (lazygit's graph package, ported and recolored by column), and `ui` (Bubble Tea model plus pure rendering helpers). All slow work (log, fetch, PRs, diffs) runs in `tea.Cmd`s so the UI never blocks.

**Tech Stack:** Go (latest from Homebrew), `github.com/charmbracelet/bubbletea` v1, `github.com/charmbracelet/lipgloss` v1, `github.com/charmbracelet/bubbles` (viewport, textinput), `github.com/gookit/color` (used by the ported graph), `github.com/samber/lo`, `github.com/stretchr/testify` (tests). External binaries: `git` (required), `delta`, `gh`, `lazygit` (optional).

**Spec:** `docs/superpowers/specs/2026-11-23-gitree-design.md` — read it before any task; this plan does not repeat its mockups.

## Global Constraints

- Module path `github.com/Stratovarius93/gitree`; binary name `gitree`; usage `gitree [path]`.
- UI copy is in English exactly as in the spec ("3 files changed", "no access to PRs: check `gh auth status`", "fetching…", "copied"). README is in English.
- Gruvbox palette (hex): red `#ea6962`, orange `#e78a4e`, yellow `#d8a657`, green `#a9b665`, aqua `#89b482`, blue `#7daea3`, purple `#d3869b`, fg `#d4be98`, gray `#928374`, dim bg `#3c3836`, separator `#504945`, dark text `#282828`.
- Graph column color order: blue, green, purple, yellow, aqua, orange, red (cycled).
- The lazygit graph port keeps lazygit's MIT copyright and license text in `internal/graph/LICENSE` and a header comment in every copied file.
- Never run a mutating git command without an explicit confirmation step in the UI. Never stash. Fetch is `git fetch --all --prune` only.
- Optional binaries missing → feature disabled with a status-bar message; never a crash or non-zero exit.
- Startup must render the first page (~300 commits) without waiting for fetch, PRs or diffs.
- All git invocations use `git -C <repoRoot>` with `GIT_TERMINAL_PROMPT=0` and `LC_ALL=C`; log fields are NUL-separated.
- Commits are authored as the repo's local identity (Stratovarius93); every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Detached HEAD and odd ref names** (`HEAD` alone in `%D`, branch names with `/`, tags named like branches): labels must render, never panic. Test in Task 2 (`TestParseDecorations` detached + slash cases).
2. **Empty or single-commit repos**: a fresh `git init` repo must open showing an empty table with "no commits", and a root commit must preview its files. Tests in Task 2 (`TestLogEmptyRepo`) and Task 5 (`TestCommitFilesRootCommit`).
3. **Very narrow or resized terminals** (down to 40 columns): widths never go negative, columns hide in the order Date → Author → Hash, no panic. Test in Task 7 (`TestComputeWidthsNarrow`).
4. **Merge commits in preview/detail**: files compared against first parent, not an empty list. Test in Task 5 (`TestCommitFilesMergeCommit`).
5. **`gh` missing, non-GitHub origin, or no access**: no PRs, a status message, no crash, and the list still loads. Test in Task 6 (`TestFetchPRsNotGitHub`, `TestFetchPRsGhMissing`).
